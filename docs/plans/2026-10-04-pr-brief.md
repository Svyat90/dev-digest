# PR Brief (why + risk brief, reading order, Files changed navigation) — Implementation Plan

Date: 2026-10-04 · Branch: feature/l05-pr-brief · Status: draft

## Goal
A reviewer opening a PR sees, at the top of the Overview tab, one PR Brief block:
the latest review's verdict banner, a one-click model-written summary, Risk areas
and a Review focus reading order next to the existing Intent and Blast radius
cards. The brief comes from exactly one bounded model call over pre-computed facts
(never the diff code), names only real files, says which facts were missing, is
cached per PR with the head SHA it describes, and every focus item / risk file
reference opens Files changed at that file and line with its findings visible.

## Assumptions
- A1 — An intent stored for an older head SHA IS sent to the model (it is "the stored intent", AC4), labelled as from an older commit in the trusted missing-input list, and the block lists it as "Intent (from an older commit)" (`missing_inputs` value `intent_stale`). No stored intent → `intent`.
- A2 — "Linked issue" is missing only when the description has at least one closing reference (intent's rules) and at least one of them could not be fetched or was empty (EC26). A description with no closing reference has no linked issue to miss.
- A3 — "Attached documents" is missing when the union of documents over the workspace's enabled agents (each agent's own + active skills', via `resolveForRun`, deduplicated by path, first wins) yields no readable document (EC3, EC4). Per-document caps stay SPEC-02's (4,000 tokens); at most `MAX_DOCUMENTS = 20` documents enter budgeting (the rest are recorded as `documents` truncated).
- A4 (revised in Revision 2, M3) — The 8,000-token cap is HARD: the model never receives more than `BRIEF_INPUT_TOKEN_BUDGET` tokens as counted by the server tokenizer over the rendered prompt. `fitBriefInput` first runs the AC5 priority steps — documents (longest, 25 % at a time, floor 500 chars), then linked issues and then the description the same way (25 % steps, floor 500 chars), then the changed-file list tail (replaced by "and N more files"). If the input still does not fit, forced-drop steps follow, in order: drop documents entirely (longest first), drop linked issues entirely, drop the description, cut the changed-file list down to zero listed files ("and N more files"), cut the blast caller file list from its tail (recorded as `blast_callers`). Every forced step records its source as truncated and sets `force_dropped: true` in the generation log. The intent, the blast summary and the missing-input list are never shortened (AC5). Those never-shortened parts plus the PR title and the fixed system/task text are bounded by construction — intent ≤ 600 chars plus ≤ 2 × 8 × 200-char scope items (intent output caps), a one-line deterministic blast summary (BR7), ≤ 5 enum labels, a title GitHub limits to 256 chars — well under the budget; T010 pins that bound with a worst-case test. If `fitBriefInput` nevertheless reports `fits: false`, the service makes NO model request and fails with `AppError('brief_input_over_budget', …, 500)`, which the client shows as "model provider unavailable" (A9: unknown codes); nothing is stored.
- A5 — The blast caller file list sent to the model is the unique caller files of `downstream[].callers`, sorted, capped at 100 (`MAX_CALLER_FILES`); only the A4 forced step may cut it further. The AC12 allow-list uses the FULL blast map (every `changed_symbols[].file` and every caller file, uncapped) plus the PR's changed files.
- A6 — Risks are sorted high → medium → low (stable within a severity) on the server BEFORE the 6-risk cut, so high risks survive EC7; the client renders the stored order.
- A7 — `end_line` is `nullable` (not optional) in both the contract and the model schema, because strict JSON-schema mode requires every key. The model schema types lines as `z.number()` (not `.int()`), so a fractional, zero or negative line is DROPPED by AC12 instead of failing the whole answer.
- A8 (revised by R1) — An invalid answer is recognised by TYPE, not by message: the OpenAI and Anthropic adapters and `MockLLMProvider` throw `InvalidModelOutputError` (new, `server/src/platform/errors.ts`, a subclass of `ExternalServiceError`, so every other caller keeps its 502 behaviour), and reviewer-core's OpenRouter provider throws `InvalidStructuredOutputError` (new, exported from `@devdigest/reviewer-core`, a plain `Error` subclass because reviewer-core has no server knowledge). `ConfigError` (no API key) is "model not configured"; anything else (timeout, 429/5xx after transport retries, network) is "model provider unavailable".
- A9 — Failure codes on `POST /pulls/:id/brief`: `invalid_model_answer` (502, new `AppError`), `external_service_error` (502) and `config_error` (500, the existing class, rethrown as is). They form the contract enum `BriefFailureCode`; the client maps any other code (including the unreachable `brief_input_over_budget`) or a network error to "model provider unavailable".
- A10 — The generation log's `attempts` is 1 whenever the model request was sent (always the case for success and invalid answers) and 0 when the generation failed before sending (config error, over-budget guard).
- A11 — AC8: the Intent and Blast radius cards are always rendered inside the block with their existing empty/loading states (they carry the Derive intent and Resync controls); when either has stored data it is shown side by side, which is what AC8 requires.
- A12 — AC25: the banner uses the newest `kind === 'review'` review (reviews arrive newest-first) — the PR score rule. It is hidden when that review's `verdict` is null; counts are its findings and its open CRITICAL findings (the `ReviewRunAccordion` blocker rule).
- A13 — Switching tabs from the header clears `file` and `line`. A `line` that is not a positive integer reads as "no line" (file header, no notice); an unknown `file` shows the AC16 notice over the normal view.
- A14 — The stored snapshot `blast` keeps `changed_symbols`, `downstream` and `summary` of the blast response the model saw, `null` when unavailable; `history` is always `null`.
- A15 — Generation reads the persisted `pr_files` (path, additions, deletions, patch); it does not refresh the PR from GitHub (NFR Network allows GitHub only for issues).
- A16 — `container.blast(logger)` constructs a `BlastService` per call because `BlastDeps` needs a logger the container does not own; the brief route passes `app.log`.

## Design

Rings (onion-architecture §2, §4):
- **Contracts (core)** — `server/src/vendor/shared/contracts/brief.ts` + identical client copy (T001).
- **Errors** — `InvalidModelOutputError` in `server/src/platform/errors.ts` (framework-free error taxonomy, onion-architecture §7) thrown by `server/src/adapters/llm/{openai,anthropic}.ts` and `server/src/adapters/mocks.ts`; `InvalidStructuredOutputError` in `reviewer-core/src/llm/openrouter.ts`, exported from `reviewer-core/src/index.ts` (T002).
- **Domain (pure)** — `server/src/domain/intent/closing-refs.ts` (new, T003): the closing-keyword issue parser, shared by `intent` and `brief` without a cross-module import (server/INSIGHTS 2026-09-30 fix (b)). `server/src/modules/brief/{types,constants,helpers}.ts` (T001, T004): line ranges from hunk headers, missing inputs, hard budget fitting, answer validation/cut, generation-error and source-error classification by type. `server/src/modules/brief/prompt.ts` (T005): model schema, untrusted-delimited messages, content-free prompt description.
- **Application** — `server/src/modules/brief/service.ts` (T010): `BriefService` with narrow `BriefDeps` (functions over container facades, never `Container`), read → pure decisions → one model call → write, one content-free generation log record (`cost_usd`, `duration_ms`, `degraded`, `force_dropped`) plus error-level records for unexpected source errors.
- **Infrastructure** — `server/src/modules/brief/repository.ts` (T010): workspace-scoped PR/repo reads, `pr_files` read, `pr_brief` read/upsert (single statement, no transaction needed).
- **Presentation** — `server/src/modules/brief/routes.ts` (T013): zod params, `getContext`, rate limit 10/min on POST, `null` literal on GET.
- **Composition root** — `server/src/platform/container.ts` (T013): `smartDiff` getter, `blast(logger)` method; `server/src/modules/index.ts` registers `brief`.
- **Client** — data hooks `client/src/lib/hooks/brief.ts` (T007); shared `client/src/components/verdict-banner/` (T006); `DiffTarget` in shared `client/src/components/diff-viewer/` (T009); `DiffTab` targeting (T011); `OverviewTab/_components/PrBriefBlock/` feature folder (T012); route wiring in `OverviewTab.tsx` / `PrDetailView.tsx` (T014).

Consistency boundary (M8): a generation describes the PR row loaded by `getPull` at its start — its title, body, persisted files and `head_sha`. The stored `head_sha` is that row's, never re-read. Facts read later (intent, blast index, documents) may be from other moments; a stale intent is labelled (A1), and a head that moves during or after generation shows the brief as out of date (AC20).

### Contracts
Both `server/src/vendor/shared/contracts/brief.ts` and `client/src/vendor/shared/contracts/brief.ts`, kept byte-identical (Zod 3):
- `RiskFileRef = { file: string; start_line: int > 0; end_line: int > 0 | null }`; `Risk.file_refs: RiskFileRef[]` (was `string[]`).
- `ReviewFocusItem = { file: string; line: int > 0; reason: string }`.
- `BriefMissingInput = enum['intent', 'intent_stale', 'blast', 'linked_issue', 'documents']`.
- `BriefTruncatableSource = enum['documents', 'linked_issues', 'description', 'files', 'blast_callers']`.
- `BriefFailureCode = enum['invalid_model_answer', 'external_service_error', 'config_error']`.
- `PrBrief = { summary: string; intent: Intent | null; blast: BlastRadius | null; risks: Risks; history: PrHistory | null; review_focus: ReviewFocusItem[]; head_sha: string; generated_at: string; missing_inputs: BriefMissingInput[]; truncated_sources: BriefTruncatableSource[]; provider: string; model: string; tokens_in: int | null; tokens_out: int | null }`.
- API: `GET /pulls/:id/brief` → `PrBrief | null` (a stored row that fails `PrBrief.safeParse` reads as `null`, EC19); `POST /pulls/:id/brief` → `PrBrief`.
No other contract file changes (the typed errors live outside `vendor/shared`, so the client copy is unaffected); `mcp/` does not read `PrBrief` (checked).

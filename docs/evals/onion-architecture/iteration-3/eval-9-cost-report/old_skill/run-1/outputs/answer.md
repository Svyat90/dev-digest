Гальмування: `CostReportService.report` робить N+1 у вкладеному циклі — на кожного агента й кожен день окремий запит `costForDay` (агенти × 90 запитів, послідовно). Виправлення: один агрегований запит у `repository.ts` (`GROUP BY agent_id, date_trunc('day', ran_at)` з `workspaceId` і діапазоном `[from, from+days)`), який повертає Map/рядки; сервіс лише розкладає їх по днях. Це інфраструктурне кільце (Drizzle і `sum()` лишаються в репозиторії), сервіс — застосунне (чиста розкладка), без drizzle. Побічно: `listAgents` теж можна об'єднати з тим самим запитом. $0.00 для днів без даних: `Number(row?.total ?? 0)` перетворює `null` (немає запусків / невідома вартість) на 0, а в домені `null` = невідомо, `0` = безкоштовно (`specs/review-flow.md`). Треба повертати `costUsd: number | null` (null, якщо немає рядків або sum = null; `parseAggregateCost` у репозиторії), рахувати `totalUsd`/`perDayAvgUsd` лише по відомих днях (середнє ділити на кількість днів із даними, не на `days`, інакше воно занижене), а UI показує "—" для null. Також: `ranAt` порівнюється з `day` без нормалізації до UTC-півночі, тож якщо `from` не опівночі, межі днів з'їжджають — нормалізуйте `from` до початку доби UTC. Структурно: роут створює `new CostReportRepository(container.db)` у `routes.ts` — краще винести в контейнер/composition root; `AgentCost` (контракт для клієнта) варто перенести в `vendor/shared/contracts` (і в копію клієнта). Роут не торкається Drizzle напряму, `arch:check` порушень тут не дасть; зміну робити малим кроком, `pnpm arch:check` має лишатися зеленим.
